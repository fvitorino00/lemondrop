# lemondrop API — Python dependencies
#
# Exact pins, no ranges. A range (`>=`) means the image you build today and the
# image you build next month can differ, and a container image is not a place to
# discover a breaking change in production. Pin exactly; upgrade deliberately.
#
# Every dependency below — and every transitive dependency they pull — ships a
# prebuilt wheel for CPython 3.12 on linux/amd64. That is why api/Dockerfile
# installs no compiler toolchain. If a future addition ever needs to compile
# from source, that is the moment to revisit that decision, not before.

# The web framework. Routing, JSON encoding and the generated OpenAPI docs all
# come from here. (Its dependency injection goes unused — no Depends anywhere —
# but it ships in the one framework either way.)
fastapi==0.143.0

# The ASGI server that actually runs the app (see CMD in the Dockerfile).
# The [standard] extra pulls uvloop (faster event loop), httptools, watchfiles
# and websockets. It is worth it here: this service is I/O-bound on downstream
# HTTP calls, so the faster event loop is doing real work, not decoration.
uvicorn[standard]==0.54.0

# The async HTTP client, used in two places. httpx.AsyncClient is the class in
# both: /health constructs one and passes it to _probe, which uses asyncio.gather
# to check the embedder and reranker concurrently instead of blocking the event
# loop on one after the other; /embed and /rerank reach the workers through the
# shared _post_upstream helper, and sharing it is what gives the two inference
# routes identical timeout policy and identical 502/504 failure semantics rather
# than letting them drift apart.
httpx==0.28.1

# ── Persistence ───────────────────────────────────────────────────────────────
# The database access layer, and the reason it is SQLAlchemy rather than raw
# asyncpg: we use Core (text() and explicit SQL), NOT the ORM. Retrieval here is
# one parameterised SELECT with a `<=>` ordering and a collection predicate, and
# an ORM would contribute a declarative model, a session lifecycle and an identity
# map that buy nothing for that query. Core still earns its place: it is the
# dialect-aware layer that knows how to parameterise pgvector and jsonb correctly
# and how to pool an async connection, which is the part hand-rolling gets wrong.
# The [asyncio] extra pulls greenlet (a compiled extension with a cp312
# manylinux x86_64 wheel) — without it `await engine.connect()` does not work.
SQLAlchemy[asyncio]==2.0.54

# The async PostgreSQL driver. It is the fast one (it is a C extension speaking
# the protocol natively rather than going through libpq), and it is async, which
# matters because the retrieval path holds a connection while the caller waits —
# a blocking driver would stall the whole event loop, including the /health
# probe, on every search. psycopg2 was the alternative and loses: it is either
# sync-only or needs an async wrapper that is slower than this anyway.
asyncpg==0.32.0

# ── No migrations here, on purpose ────────────────────────────────────────────
# Alembic used to sit in this file. It has moved to requirements-dev.txt, and
# the reason is worth stating so nobody "helpfully" puts it back: alembic is a
# schema-migration tool, and the API container never runs migrations. Migrations
# run out-of-band, as a separate privileged step — CREATE EXTENSION vector needs
# a role the application deliberately does not have (see api/alembic/README.md).
# Shipping the tool anyway is image bloat plus unused attack surface: a
# credentialed database driver and a DDL executor sitting in a production image
# where no code path can reach them.
